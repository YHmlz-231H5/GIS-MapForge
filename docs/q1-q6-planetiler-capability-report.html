Q1–Q6 × Planetiler 能力对照报告

生成日期：2026-07-23 · 范围：app-map-downloader「生成 PMTiles」弹窗
对照对象：本地 tools/planetiler.jar --help + Planetiler config-example.properties + OpenMapTiles profile README

结论（先看这个）

当前 UI 的 Q1–Q6 几乎全部不会改变 PMTiles 内容。 它们只写入任务的 options.layers 并落库，但 planetiler-convert.ts 没有把它们映射成 --only-layers / --exclude-layers 或其它 CLI 参数。 真正生效的只有弹窗底部的 zoom max、bbox clip， 以及代码里写死/默认的 java_heap、download_aux。

Planetiler 确实支持按 OpenMapTiles 图层整层开关（only_layers / exclude_layers），但不支持 UI 里那种细粒度语义 （例如「只要城市地名」「建筑仅 z13+」「州级边界」）——那些需要改 Profile / 后处理 / 样式过滤。

2. Planetiler / OpenMapTiles 官方真正支持什么

图层级开关（官方明确支持）

  • --only-layers=water,transportation,...
  • --exclude-layers=poi,housenumber,...

出处：planetiler-openmaptiles README「Customizing」；config-example only_layers / exclude_layers；本地 jar --help 已确认。

粒度：整层。例如可去掉整个 poi 或整个 building，不能说「只要 primary 道路」。

全局几何 / 范围（官方支持）

  • bounds / bbox（本应用用 --bbox）
  • minzoom / maxzoom（默认 max 14，最高约 16）
  • simplify_tolerance、特征最小尺寸等

出处：config-example.properties；本机 --help。

图层内微调（官方有，但与 Q1–Q6 不对齐）

官方参数作用能否替代某个 Q？
building_merge_z13 z13 合并邻近建筑（默认 true；关闭可加速） ≠ Q4「z13+ only」 —— 控制合并策略，不是「从哪级开始出建筑」
transportation_z13_paths 是否在 z13 显示小路 ≠ Q3 —— 细节开关，不是 roads/labels/none
transportation_name_* 路名合并 / brunnel / shield 等 ≠ Q3 roads+labels
boundary_country_names / boundary_osm_only 边界层属性与数据源 ≠ Q6 boundary_state
languages / Wikidata 多语言标签 与 Q 无关

官方说明：更细的图层逻辑改动需要 fork Profile（改 Java Layer 类），不能靠现成 UI 语义一键完成。

4. 概念澄清：三种「过滤」别混在一起

  1. 下载 OSM 时过滤（Overpass 查询）—— 本项目当前「生成 PMTiles」弹窗不负责这件事； OSM 下载通常是区域全量。
  2. Planetiler 写入瓦片时过滤（only/exclude-layers、maxzoom、bbox）—— 官方支持；本应用目前只做了 bbox + maxzoom。
  3. 地图样式显示过滤（MapLibre style 不画某些 layer）—— 数据仍在 PMTiles 里；体积不减。Q1–Q6 注释里写过「curated subset to render in style」， 但产品文案却放在「生成 PMTiles」里，容易让人以为会改变档案内容。

5. 与你期望的「两种模式」对齐建议（供下一步改 UI，本次不改代码）

模式 A · 全量

不传 only/exclude-layers，OpenMapTiles 默认全层输出。

仍暴露：maxzoom、bbox（必要时 heap）。

适合：离线底图、预览要对齐完整图层清单。

模式 B · 自定义（仅官方能落地的）

用复选框映射到 --exclude-layers=...（或 only）。

建议清单（与 OMT 图层一一对应）：

water, waterway, water_name, landcover, landuse, park, boundary, transportation, transportation_name, building, place, poi, housenumber, mountain_peak, aeroway, aerodrome_label, …

不要再放：用途四档、places 等级、buildings z13+、boundary_state（除非后续实现 Profile）。
